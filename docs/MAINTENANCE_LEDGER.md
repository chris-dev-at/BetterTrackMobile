**VP-4 board note for the coordinator (post with the implementation):**

> aligned — the app's S2 session now survives process death under the same five lock edges and the same 7-day TTL.
> Scope: the pv (per-portfolio vault) endpoint custody only; the v1 account-vault custody never persisted the VK, so #1640 had nothing to retire on mobile.
> At rest: K_dev only, sealed under a non-extractable AndroidKeyStore AES-256-GCM key; no password, phrase, entropy or content key is ever written.
> Record: {version, accountId, iv‖ct, createdAt, expiresAt} in the pv endpoint prefs; AAD binds accountId and both instants, so editing the file cannot extend a session.
> Lock edges: explicit lock, sign-out, account switch, PIN idle lock, TTL — the first four write the per-account device-locked marker FIRST, then zero K_dev, then drop the record.
> The marker is cleared only by a successful device-password unlock (incl. first setup and a password change); an unreadable marker refuses the resume.
> Resume after process death: marker → lockout window → endpoint password material → record (expired dropped) → wrap check → re-check → install; never re-persisted, so the TTL stays absolute from the creating unlock.
> One timer: the app lock's idle edge (the cold-start PIN gate is not a lock); the TTL is enforced on the next vault read, no second clock.
> Still dormant: ParanoidVaultsFlags.enabled = false; nothing new is wired into the app graph.
> Questions for the platform: none blocking; if the web wants the instants in its record AAD too, the mobile layout is in tools/domain-vectors/PINNED_AT.
